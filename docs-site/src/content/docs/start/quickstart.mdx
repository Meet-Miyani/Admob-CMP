This guide walks through rendering a test ad unit on Android and iOS using Compose Multiplatform, followed by the complete configuration required for a production launch.

## Step 1: Add the facade dependency

Add the umbrella library coordinate to your shared module's build script:

```kotlin
// shared/build.gradle.kts
kotlin {
    sourceSets {
        commonMain.dependencies {
            implementation("dev.avinya.ads:admob-cmp:1.1.1")
        }
    }
}
```

The Android dependencies for GMA Next-Gen and UMP arrive transitively via Maven. On iOS, native frameworks must be linked in Xcode via Swift Package Manager; see [iOS setup](/start/ios-setup/) for details.

If your project executes Kotlin/Native unit tests (`:shared:iosSimulatorArm64Test`), also apply the Gradle plugin to prevent linker errors:

```kotlin
// shared/build.gradle.kts
plugins {
    id("dev.avinya.ads.admob-cmp") version "1.1.1"
}
```

For full version catalog instructions, see [Installation](/start/installation/).

## Step 2: Configure test application identity

Google Mobile Ads requires a valid Application Identifier declared in platform manifest files before initialisation. For test purposes, use Google's official test Application IDs:

On Android, add the metadata entry to `androidApp/src/main/AndroidManifest.xml`:

```xml
<manifest xmlns:android="http://schemas.android.com/apk/res/android">
    <application>
        <meta-data
            android:name="com.google.android.gms.ads.APPLICATION_ID"
            android:value="ca-app-pub-3940256099942544~3347511713" />
    </application>
</manifest>
```

On iOS, add the application identifier to `iosApp/iosApp/Info.plist`:

```xml
<key>GADApplicationIdentifier</key>
<string>ca-app-pub-3940256099942544~1458002511</string>
```

## Step 3: Create AdManager and show a test banner

In your top-level `@Composable` entry point, obtain the process-wide `AdManager` singleton using `rememberAdManager()` and trigger test initialisation inside a `LaunchedEffect`:

```kotlin
import androidx.compose.runtime.CompositionLocalProvider
import dev.avinya.ads.LocalAdManager

@Composable
fun App() {
    val adManager = rememberAdManager()

    LaunchedEffect(adManager) {
        adManager.gatherConsentAndInitialize(
            AdConfig(
                androidAppId = TestAdIds.ANDROID_APP_ID,
                iosAppId = TestAdIds.IOS_APP_ID,
                testMode = true,
            )
        )
    }

    val status by adManager.status.collectAsState()
    if (status is AdManagerStatus.Ready) {
        CompositionLocalProvider(LocalAdManager provides adManager) {
            MainAdScreen()
        }
    }
}

@Composable
fun MainAdScreen() {
    val placement = remember {
        AdPlacement(
            id = "main_banner",
            format = AdFormat.Banner,
            androidAdUnitId = TestAdIds.ANDROID_BANNER,
            iosAdUnitId = TestAdIds.IOS_BANNER,
            strictTestMode = true,
        )
    }

    BannerAdView(
        placement = placement,
        modifier = Modifier.fillMaxWidth(),
        onEvent = { event ->
            when (event) {
                is AdEvent.Loaded -> println("Test banner loaded successfully")
                is AdEvent.LoadFailed -> println("Test banner failed to load: ${event.error}")
                else -> Unit
            }
        },
    )
}
```

Setting `strictTestMode = true` ensures that the placement throws an exception if configured with a non-test ad unit ID in debug builds.

## Step 4: Verify the test ad renders

Run the application on an Android emulator or iOS simulator:
1. Verify that `adManager.status` transitions from `AdManagerStatus.Initializing` to `AdManagerStatus.Ready`.
2. Confirm that the `BannerAdView` displays Google's "Nice job! This is an ad title" test banner overlay.
3. Inspect console logs for `Test banner loaded successfully`.

## Moving to production

Transitioning from a local test setup to a production distribution involves configuring legal consent flows, platform tracking, and control-plane requirements.

### What is the correct initialisation order?

Production ad requests in GDPR regions or on iOS require explicit handling of user consent and App Tracking Transparency (ATT). The canonical sequence mirrors the library's demo startup flow:

<InitSequence />

1. **User Messaging Platform (UMP)**: Gathers European Economic Area (EEA) and UK privacy consent.
2. **App Tracking Transparency (ATT)**: On iOS, requests authorization to access the Identifier for Advertisers (IDFA).
3. **Google Mobile Ads Initialisation**: Initialises ad serving according to user consent choices.

To enforce this order, register an `AdInitializationHook` targeting the `BeforeMobileAdsInitialize` phase. This hook executes conditionally on iOS prior to native SDK initialisation:

```kotlin
@Composable
fun ProductionApp() {
    val adManager = rememberAdManager()
    val status by adManager.status.collectAsState()

    val config = remember(adManager) {
        AdConfig(
            androidAppId = "ca-app-pub-YOUR_PUBLISHER_ID~YOUR_ANDROID_APP_ID",
            iosAppId = "ca-app-pub-YOUR_PUBLISHER_ID~YOUR_IOS_APP_ID",
            testMode = false,
            initializationHooks = listOf(
                object : AdInitializationHook {
                    override suspend fun onPhase(
                        phase: AdInitializationPhase,
                        config: AdConfig,
                    ) {
                        if (phase == AdInitializationPhase.BeforeMobileAdsInitialize) {
                            // Prompt for ATT on iOS prior to native GMA initialisation
                            adManager.tracking.requestAuthorization()
                        }
                    }
                }
            ),
        )
    }

    LaunchedEffect(adManager, config) {
        // Gather UMP consent (shows form if required) and initialise
        adManager.initialize(
            config = config,
            consentMode = ConsentMode.GatherBeforeInitialize,
        )
    }

    when (status) {
        AdManagerStatus.Ready -> {
            CompositionLocalProvider(LocalAdManager provides adManager) {
                ContentScreen(adManager)
            }
        }
        is AdManagerStatus.Failed -> ErrorScreen(status as AdManagerStatus.Failed)
        else -> LoadingScreen()
    }
}
```

On Android, `adManager.tracking.requestAuthorization()` resolves immediately as `AdTrackingAuthorization.NotApplicable`.

### Production checklist

Replacing test IDs with production strings is only one part of preparing for release. Complete the following control-plane steps before distributing your application:

<Steps>

1. **Register Applications in AdMob Console**
   Create separate Android and iOS app entries in your Google AdMob account to obtain production Application IDs.

2. **Create Production Ad Units**
   Generate placement-specific Ad Unit IDs for Banner, Interstitial, Rewarded, or Native formats in the AdMob console.

3. **Configure AdMob Privacy & Messaging**
   Set up GDPR/TCF consent forms and US state privacy messages in the AdMob console so UMP can present valid consent dialogs.

4. **Update Application Metadata & Code Configurations**
   Replace sample Application IDs in `AndroidManifest.xml` and `Info.plist`, and update `AdPlacement` identifiers in shared Kotlin code.

5. **Configure iOS App Tracking Transparency**
   Add `NSUserTrackingUsageDescription` to `Info.plist` and confirm the `requestAuthorization()` hook executes before native initialisation.

6. **Complete Store Privacy Disclosures**
   Fill out Google Play Data Safety and Apple App Store Privacy Nutrition Labels reflecting SDK data practices. See [Play Data safety](/privacy/play-data-safety/).

7. **Register Test Devices**
   Add developer test device IDs via `GlobalRequestConfiguration.testDeviceIds` or `AdDebugOptions.testDeviceIds` to test live ad units safely without risking account suspension for invalid impressions.

8. **Validate Release Builds**
   Perform final validation using signed release builds on physical devices across both platforms.

</Steps>
