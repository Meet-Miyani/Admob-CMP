## What the library does

AdMob CMP is a Kotlin Multiplatform (KMP) library that provides a unified Kotlin API for Google Mobile Ads (GMA) and User Messaging Platform (UMP) consent across Android and iOS. Built primarily for Compose Multiplatform applications, it enables developers to manage ad lifecycles, load states, and user privacy compliance using declarative Kotlin constructs.

The published facade dependency coordinate is `dev.avinya.ads:admob-cmp:1.1.0`. The library wraps Google Mobile Ads SDKs on both platforms:
- **Android**: Binds the GMA Next-Gen SDK (version 1.3.0) and UMP SDK (version 4.0.0) transitively via Maven.
- **iOS**: Provides cinterop bindings for the GMA iOS SDK (version 13.x) and UMP iOS SDK (version 3.x), with the host application linking Google's framework binaries directly via Swift Package Manager.

## How the modules are structured

The project is structured into two main modules behind the umbrella coordinate:
- `admob-cmp-core`: Contains core controllers (`BannerAdController`, `InterstitialAdController`, etc.), lifecycle state machines, ad caching logic, retry policies, and platform-specific adapters. Non-Compose KMP applications can depend directly on this module.
- `admob-cmp-compose`: Provides Compose Multiplatform composable abstractions, including `rememberAdManager()`, `BannerAdView`, and `NativeAdView`.

Platform specificities remain strictly isolated. Manifest metadata and application identity reside in native configuration files (`AndroidManifest.xml` on Android and `Info.plist` on iOS), while all ad management, state flows, and consent handling take place in shared Kotlin code.

## Which ad formats are supported?

The library supports six distinct ad format configurations across five core ad types:

| Format | Controller / API | Composable View | Primary Placement Guide |
|---|---|---|---|
| Banner (Standard & Adaptive) | `adManager.banner(placement)` | `BannerAdView` | [Banner ads](/formats/banner/) |
| Interstitial | `adManager.interstitial(placement)` | — | [Interstitial ads](/formats/interstitial/) |
| Rewarded | `adManager.rewarded(placement)` | — | [Rewarded ads](/formats/rewarded/) |
| Rewarded Interstitial | `adManager.rewardedInterstitial(placement)` | — | [Rewarded ads](/formats/rewarded/) |
| App-Open | `adManager.appOpen(placement)` | — | [App-open ads](/formats/app-open/) |
| Native | `adManager.nativeAd(placement)` | `NativeAdView` | [Native ads](/formats/native/) |

Controllers are placement-keyed singletons retained across screen recompositions, ensuring load state continuity and preventing redundant ad requests.

## Core capabilities

AdMob CMP addresses common ad-integration challenges in shared Kotlin code:

1. **Placement-Keyed Controller Management**: Maintains static, placement-specific controllers across UI recompositions.
2. **Automated Ad Caching & Retry**: Implements TTL-based eviction, backoff retry policies, and customizable caching parameters (`AdCachePolicy`, `AdExpirationPolicy`, `AdRetryPolicy`).
3. **Consent-Gated Requests**: Automatically checks `canRequestAds` before making network requests, preventing policy violations from premature loading.
4. **Unified Reactive Event Stream**: Exposes a single `AdEvent` `StateFlow` covering `Loaded`, `LoadFailed`, `Impression`, `Clicked`, `Paid`, and `RewardEarned`.

### Intentional boundaries and scope

- **No Bundled Mediation Adapters**: Mediation network adapters (such as Meta or Unity Ads) must be added to native project dependencies directly to avoid locking GMA SDK versions.
- **Bindings-Only iOS Distribution**: Objective-C cinterop bindings are shipped without embedding binary dependencies. Host applications link `GoogleMobileAds` via Swift Package Manager to avoid Objective-C duplicate symbol conflicts when mediation adapters are used.
- **KMP Scope**: Designed specifically for mobile targets (Android and iOS). Desktop and Web targets are not supported ad-serving platforms.
- **Naming Context**: The acronym CMP refers to Compose Multiplatform within this project. While the library integrates Google's UMP SDK for GDPR and TCF compliance, it is an SDK integration wrapper rather than a Consent Management Platform vendor.
