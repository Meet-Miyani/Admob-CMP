This guide describes how to add AdMob CMP dependencies to a Kotlin Multiplatform project, align versions using Gradle version catalogs, and resolve platform build requirements.

## Repository Setup

Ensure your project's repository configuration includes both Maven Central and Google's Maven repository. Add `google()` to your repository declarations in `settings.gradle.kts`:

```kotlin
// settings.gradle.kts
dependencyResolutionManagement {
    repositories {
        google()
        mavenCentral()
    }
}
```

`google()` is required because Google Mobile Ads transitive dependencies (such as Cronet) are hosted on Google's Maven repository rather than Maven Central.

## Dependency Coordinate Selection

AdMob CMP is published on Maven Central under the group `dev.avinya.ads`.

### Umbrella Facade Artifact (Recommended)

Most Compose Multiplatform applications should depend on the umbrella coordinate:

```kotlin
// shared/build.gradle.kts
kotlin {
    sourceSets {
        commonMain.dependencies {
            implementation("dev.avinya.ads:admob-cmp:1.1.0")
        }
    }
}
```

The umbrella artifact includes both `admob-cmp-core` and `admob-cmp-compose`.

### Granular Module Dependencies

For projects that do not use Compose Multiplatform or require decoupled architectures, the underlying modules can be imported individually:

- `dev.avinya.ads:admob-cmp-core:1.1.0`: Contains core controllers (`AdManager`, `BannerAdController`, `InterstitialAdController`), lifecycle state machines, ad caching, retry policies, and platform adapters. Has no Compose Multiplatform dependencies.
- `dev.avinya.ads:admob-cmp-compose:1.1.0`: Contains Compose Multiplatform composables (`rememberAdManager()`, `BannerAdView`, `NativeAdView`). Depends on `admob-cmp-core`.

## Version Catalog Configuration

For multi-module Gradle projects, manage library dependencies and plugin definitions using `gradle/libs.versions.toml`:

```toml
# gradle/libs.versions.toml
[versions]
admob-cmp = "1.1.0"

[libraries]
admob-cmp = { module = "dev.avinya.ads:admob-cmp", version.ref = "admob-cmp" }
admob-cmp-core = { module = "dev.avinya.ads:admob-cmp-core", version.ref = "admob-cmp" }
admob-cmp-compose = { module = "dev.avinya.ads:admob-cmp-compose", version.ref = "admob-cmp" }

[plugins]
admob-cmp = { id = "dev.avinya.ads.admob-cmp", version.ref = "admob-cmp" }
```

In your module build script:

```kotlin
// shared/build.gradle.kts
kotlin {
    sourceSets {
        commonMain.dependencies {
            implementation(libs.admob.cmp)
        }
    }
}
```

Maintaining identical versions across library coordinates and the Gradle plugin ensures ABI compatibility.

## Gradle Plugin & Kotlin/Native Test Linking

When running Kotlin/Native unit tests (such as `./gradlew :shared:iosSimulatorArm64Test`), the Kotlin compiler produces a standalone test binary without Xcode or Swift Package Manager build phases. If shared code references native Google Mobile Ads Objective-C symbols, the linker fails with undefined symbol errors (`_OBJC_CLASS_$_GADMobileAds`, `_OBJC_CLASS_$_GADRequest`, etc.).

To resolve Kotlin/Native test linking, apply the `dev.avinya.ads.admob-cmp` Gradle plugin to modules containing Kotlin/Native test targets:

```kotlin
// shared/build.gradle.kts
plugins {
    id("dev.avinya.ads.admob-cmp") version "1.1.0"
}
```

### Plugin Responsibilities

- **XCFramework Download**: Automatically fetches the required GoogleMobileAds and UserMessagingPlatform XCFramework binaries into `build/admob-cmp-ios-frameworks/`.
- **Test-Only Linker Configuration**: Injects `-framework GoogleMobileAds`, `-framework UserMessagingPlatform`, and `-framework JavaScriptCore` linker flags exclusively into test compilation tasks.
- **Production Isolation**: Leaves production application framework builds unaffected, allowing Xcode to handle framework linkage via SPM.
- **Diagnostic Task Registration**: Provides the `./gradlew :admob-cmp-core:doctorIos` verification task.

<Aside type="note">
Adding additional SPM packages to Xcode will not fix `:linkDebugTestIosSimulatorArm64` failures, as SPM dependencies are not consulted during standalone Kotlin/Native compiler invocations. The Gradle plugin is the required solution.
</Aside>

## Verifying the Installation

Execute the following verification commands to confirm correct dependency resolution and framework linking:

```bash
# Run iOS setup diagnostic checks
./gradlew :admob-cmp-core:doctorIos

# Execute Kotlin/Native test compilation and execution
./gradlew :shared:iosSimulatorArm64Test

# Execute Android JVM unit tests
./gradlew :shared:testAndroidHostTest
```

`doctorIos` verifies framework download caches, Xcode project references, and required `Info.plist` key declarations. Successful execution of test tasks confirms that native bindings link correctly across all targets.
